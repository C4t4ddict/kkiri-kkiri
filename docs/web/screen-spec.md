# 화면 정의서

## 1. 목적과 범위

끼리끼리 웹의 정보 구조, URL, 사용자 권한, 주요 컴포넌트, API 의존성, 반응형 동작을 정의한다. 현재 `web/`에 구현된 화면은 유지·확장하고, 앱 기능과의 차이를 단계적으로 줄인다.

## 2. 사용자 유형

| 유형      | 판정 기준                                                           | 접근 범위                                      |
| --------- | ------------------------------------------------------------------- | ---------------------------------------------- |
| 비회원    | 인증 토큰 없음                                                      | 로그인, 회원가입, 이메일 인증, 비밀번호 재설정 |
| 일반 회원 | `account_type=GENERAL`                                              | 전국 모집 조회·작성·지원, 개인 활동 관리       |
| 학생 회원 | `email_verified=true`, `account_type=STUDENT`, `school_domain` 존재 | 전국 및 동일 학교 모집 조회·작성·지원          |
| 관리자    | `is_admin=true`                                                     | 일반 기능과 운영관리                           |

학교 모집 접근은 서버의 `canAccessRecruitment` 판정을 최종 기준으로 한다. UI에서 메뉴를 숨겨도 API 권한 검사를 대체하지 않는다.

## 3. 전역 레이아웃

### 3.1 데스크톱

- 좌측 고정 사이드바: 로고, 홈, 정보, 활동, 매칭, 마이페이지
- 상단 바: 통합 검색 진입점, 알림, 사용자 메뉴
- 본문: 최대 1,280px, 12열 그리드
- 상세 작업: 목록과 상세를 5:7 또는 4:8 분할 가능

### 3.2 태블릿

- 축소 사이드바 또는 아이콘 레일
- 본문 8열 그리드
- 상세 패널은 Drawer 또는 전체 화면으로 전환

### 3.3 모바일 웹

- 앱과 같은 상단 `끼리끼리` 로고와 하단 5탭 내비게이션
- 본문 4열 그리드
- 하단 고정 UI는 safe area를 반영
- hover에 의존하지 않고 모든 작업을 탭으로 수행 가능해야 함

## 5. 핵심 화면 정의

### HOME-01 홈

**목표**: 사용자가 로그인 직후 지원할 활동, 팀 모집, 진행 중 목표를 10초 안에 파악한다.

**구성**

1. 환영 영역: 사용자 이름, 오늘의 핵심 안내, 정보 탭 CTA
2. 요약 지표: 접수 중 활동, 나의 지원, 모집 중 팀, 미완료 목표
3. 마감 임박 활동: 포스터형 가로 카드, `접수중 D-n` 상태
4. 추천 활동: 카테고리 기반 카드 목록
5. 내 활동 스냅샷: 현재 활동명, 역할, 오늘의 목표 진행률
6. 모집 현황: 활동별 모집글 수를 `+n` 배지로 표시

**상태**

- 활동 없음: 관심 카테고리 선택 CTA
- 팀 없음: 매칭 탭 이동 CTA
- API 일부 실패: 실패한 섹션만 재시도하며 나머지는 유지

### INFO-01 활동 정보 목록

**목표**: 사용자가 조건에 맞는 공모전·대외활동을 빠르게 찾는다.

**필터**

- 키워드, 카테고리, 접수 상태, 대상, 온·오프라인, 지역
- 선택 필터는 URL query string에 보존
- 앱 홈·정보·매칭에서 같은 카테고리 사전을 사용

**카드 필수 정보**

- 원본 비율 포스터, 활동명, 주최기관, 카테고리
- 신청 기간과 `예정`·`접수중 D-n`·`마감`
- 상금 요약, 관심 활동 하트, 진행 중 모집글 수

**데스크톱**: 좌측 필터 패널 + 3열 카드. **모바일**: 필터 Bottom Sheet + 1열 카드.

### INFO-02 활동 상세

**구성**

- 원본 비율 포스터와 제목·상태·저장 버튼
- 대상, 주최, 지역, 운영 기간, 신청 기간, 상금
- 줄바꿈을 보존한 상세 내용
- 이메일은 복사 동작, 전화번호는 `tel:` 링크
- 관련 모집글 목록과 모집글 상세 이동

### ACT-01 활동 대시보드

**목표**: 한 활동의 목표·협업·성과를 한 화면에서 관리한다.

**데스크톱 배치**

- 상단: 활동 선택, 역할, 활동 편집, 지난 활동, 알림
- 1행: 진행 링 5열 + 오늘 목표 7열
- 2행: 캘린더 8열 + 히트맵 4열
- 3행: 공지사항 6열 + 이슈트래커 6열

**위젯**

- `ProgressRings`: 전체·일일·주간·월간 진행률, 최초 진입 시 700~1,000ms 애니메이션
- `GoalBoard`: 일일 기본 탭, 주간·월간 독립 목록, 상태 클릭 변경
- `ActivityCalendar`: 남은 일일 목표 수, 최대 3개 기간 목표 선, 표시 설정
- `Heatmap`: 월 이동과 일별 완료 강도
- `NoticeBoard`: 제목 변경, 작성, 더보기, 상세·댓글 모달
- `IssueTracker`: 오늘 범위의 목표만 표시

### MATCH-01 모집글 목록

**목표**: 사용자가 학교·전국 범위에서 조건에 맞는 팀을 찾는다.

**구성**

- 학교/전국 세그먼트: 일반 회원에게 학교 탭은 인증 안내 상태
- 카테고리·활동·기간·인원·진행 상태 필터
- 선택 카테고리 축소 애니메이션
- 모집 카드: 활동, 글 제목, 기간, 인원, 방식, 범위, 작성자
- 작성 CTA와 관심 활동에서 불러오기

### MY-01 마이페이지

**구성**

- 프로필 요약: 사진, 이름, 이메일, 학교 인증 상태
- 최대 3열 메뉴 그리드, 사용자 편집 순서 지원은 추가 저장 API 필요
- 일반 메뉴: 나의 평가, 팀원 평가, 설정, 관심 활동, 나의 모집, 나의 지원, 수상 내역, 친구, 개발자에게 한마디
- 관리자만 운영관리 메뉴 노출

## 6. 공통 상태 규칙

| 상태          | 표현                         | 동작                    |
| ------------- | ---------------------------- | ----------------------- |
| 초기 로딩     | Skeleton                     | 기존 레이아웃 크기 유지 |
| 갱신          | 콘텐츠 유지 + 작은 진행 표시 | 중복 요청 방지          |
| 빈 상태       | 이유 + 1개 CTA               | 오류처럼 표현하지 않음  |
| 네트워크 오류 | 섹션 오류 카드               | 재시도 제공             |
| 401           | 세션 만료 안내               | 로그인 이동             |
| 403           | 접근 범위 설명               | 가능한 대체 경로 제공   |
| 404           | 존재하지 않음                | 상위 목록 이동          |
| 저장 성공     | Toast                        | 화면 상태 즉시 갱신     |
| 파괴 작업     | 확인 Dialog                  | 대상명을 명시           |

## 7. 접근성 완료 기준

- 키보드만으로 모든 기능에 접근 가능
- 포커스 표시를 제거하지 않음
- 아이콘 버튼에 한국어 accessible name 제공
- 색상 외 텍스트·아이콘으로 상태를 함께 표시
- 모달은 포커스 트랩, ESC 닫기, 닫힌 후 트리거로 포커스 복귀
- 본문 대비 WCAG AA 준수
- 애니메이션 감소 설정 지원
