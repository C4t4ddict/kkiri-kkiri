# 디자인 컨벤션

## 1. 디자인 철학

끼리끼리는 **함께할 사람을 찾고, 목표를 실행하고, 성장 기록을 남기는 서비스**다. 웹에서도 다음 인상이 일관되어야 한다.

1. **함께 성장함**: 겹치는 링, 연결선, 팀 카드로 협업과 누적 성장을 표현한다.
2. **부드러운 추진력**: 선명한 보라색을 행동에 사용하고 연한 보라색 면으로 부담을 줄인다.
3. **명확한 상태**: 모집·지원·목표의 현재 상태를 한눈에 구분한다.
4. **기록의 신뢰성**: 데이터가 많은 화면도 정돈된 간격과 계층으로 읽기 쉽게 만든다.

앱과 웹은 같은 브랜드를 공유하지만 배치까지 동일할 필요는 없다. 앱은 순차 탐색, 웹은 비교와 병렬 작업을 우선한다.

## 2. 디자인 토큰

### 2.1 색상

| 토큰             | 값        | 용도                        |
| ---------------- | --------- | --------------------------- |
| `brand.primary`  | `#7A5AF8` | 주 행동, 선택 탭, 링크      |
| `brand.dark`     | `#5B21B6` | 강조 텍스트, 그래프 외곽 링 |
| `brand.light`    | `#A78BFA` | 보조 그래프, hover 강조     |
| `brand.soft`     | `#EEEAFE` | 선택 배경, 진행 트랙        |
| `brand.surface`  | `#F4F1FF` | 아이콘 배경, 연한 카드      |
| `text.primary`   | `#101828` | 제목·본문                   |
| `text.secondary` | `#667085` | 설명·메타데이터             |
| `text.tertiary`  | `#98A2B3` | 비활성·placeholder          |
| `border.default` | `#E4E7EC` | 카드·입력 경계              |
| `surface.page`   | `#F7F8FC` | 웹 페이지 배경              |
| `surface.card`   | `#FFFFFF` | 카드·모달                   |
| `success`        | `#027A48` | 완료·승인                   |
| `warning`        | `#B54708` | 예정·검토 중                |
| `danger`         | `#B42318` | 오류·삭제·거절              |

새 임의 보라색을 추가하지 않는다. 기간 목표처럼 여러 보라색이 필요한 경우 승인된 팔레트 `#53389E`, `#6941C6`, `#7A5AF8`, `#7F56D9`, `#9E77ED`, `#B692F6` 안에서 사용한다.

### 2.2 타이포그래피

- 기본 글꼴: `Noto Sans KR`, `system-ui`, `sans-serif`
- 숫자·영문도 같은 글꼴을 사용해 시각적 이질감을 줄인다.
- 제목은 `700~900`, 본문은 `400~600` 범위를 사용한다.
- 한글 제목에 과도한 자간을 넣지 않는다.

| 역할          | 크기/행간 | 무게    |
| ------------- | --------- | ------- |
| Display       | `40/52`   | 800~900 |
| Page title    | `32/42`   | 800     |
| Section title | `22/30`   | 800     |
| Card title    | `16/24`   | 700     |
| Body          | `14/22`   | 400~500 |
| Caption       | `12/18`   | 500~700 |

### 2.3 간격·크기

- 기본 4px 배수 체계: `4, 8, 12, 16, 20, 24, 32, 40, 48, 64`
- 카드 내부 기본 여백: 모바일 16px, 데스크톱 20~24px
- 페이지 섹션 간격: 32~48px
- 클릭 영역 최소: 44×44px

### 2.4 Radius와 그림자

| 토큰          | 값    | 용도                 |
| ------------- | ----- | -------------------- |
| `radius.sm`   | 12px  | 입력·작은 버튼       |
| `radius.md`   | 16px  | 목록 행·아이콘 블록  |
| `radius.lg`   | 20px  | 카드                 |
| `radius.xl`   | 28px  | 대시보드·프로필 카드 |
| `radius.full` | 999px | 배지·pill            |

그림자는 계층이 필요한 hover, floating action, modal에만 사용한다. 기본 카드는 1px border를 우선한다.

## 3. 레이아웃

| 구간    | 너비        | 그리드 | 내비게이션            |
| ------- | ----------- | ------ | --------------------- |
| Wide    | 1280px 이상 | 12열   | 246px 사이드바        |
| Desktop | 1024~1279px | 12열   | 210px 사이드바        |
| Tablet  | 768~1023px  | 8열    | 축소 레일 또는 Drawer |
| Mobile  | 360~767px   | 4열    | 상단 로고 + 하단 5탭  |

- 본문 최대 너비는 1,280px로 제한한다.
- 포스터는 원본 비율을 보존하고 카드 목록에서만 정해진 프레임 안에 `object-fit: cover`를 허용한다.
- 상세 화면에서는 `object-fit: contain` 또는 실제 비율로 표시한다.
- 텍스트가 긴 활동명은 1줄 ellipsis를 기본으로 하며 높이가 늘어나지 않게 한다.

## 4. 컴포넌트 규칙

### 버튼

- 한 영역의 Primary button은 하나만 둔다.
- Secondary는 연한 보라색, Tertiary는 테두리 또는 텍스트 버튼을 사용한다.
- 삭제는 danger 색상이며 저장 버튼 옆에 같은 강조도로 배치하지 않는다.
- 로딩 시 너비를 유지하고 중복 클릭을 막는다.

### 카드

- 카드 전체가 클릭 가능하면 내부에 중복 상세 버튼을 두지 않는다.
- 상태, 제목, 메타정보, 행동 순으로 계층을 유지한다.
- 모집글 수 `+n`, 댓글 수 `+n`, 읽지 않은 수는 같은 badge 문법을 사용한다.

### 입력

- label을 placeholder로 대체하지 않는다.
- 오류는 입력 아래에 원인과 해결 방법을 적는다.
- 날짜는 `YYYY-MM-DD`를 API 기준으로 사용하고 UI에서는 한국어 표현을 허용한다.
- 금액 입력은 원 단위 정수로 저장하고 화면에서 구분자를 적용한다.

### Modal과 Drawer

- 단일 확인·작성은 Modal, 탐색 맥락이 긴 상세는 Drawer 또는 route를 사용한다.
- 시스템 `alert`는 웹 기능 UI에 사용하지 않는다.
- 삭제·취소·3개 제한 같은 경고는 서비스 스타일 Dialog로 표시한다.

### 상태 Badge

| 도메인    | 상태       | 표현            |
| --------- | ---------- | --------------- |
| 활동 접수 | 예정       | warning surface |
| 활동 접수 | 접수중 D-n | primary surface |
| 활동 접수 | 마감       | neutral surface |
| 목표      | 미진행     | neutral         |
| 목표      | 진행중     | primary         |
| 목표      | 완료       | success         |
| 지원      | 검토중     | warning         |
| 지원      | 합류 제안  | primary         |
| 지원      | 승인       | success         |
| 지원      | 거절·취소  | danger          |

## 5. 아이콘·이미지

- 웹은 `lucide-react`, 앱은 현재 아이콘 라이브러리를 사용하되 의미를 맞춘다.
- 이모티콘을 제품 아이콘 대신 사용하지 않는다.
- 같은 기능은 화면마다 같은 아이콘을 사용한다.
- 아이콘만 있는 버튼은 tooltip과 accessible name을 제공한다.
- 프로필·활동 이미지는 업로드 실패와 없는 상태를 구분한다.

## 6. 모션

| 유형             | 시간        | easing                   |
| ---------------- | ----------- | ------------------------ |
| hover·색상       | 160ms       | ease-out                 |
| 카드·Drawer 전환 | 200~240ms   | cubic-bezier(.2,.8,.2,1) |
| 진행 링          | 700~1,000ms | cubic-bezier(.2,.8,.2,1) |
| drag reorder     | 180~240ms   | spring 계열              |

- 모션은 상태 변화를 설명해야 하며 장식만을 위해 반복하지 않는다.
- `prefers-reduced-motion: reduce`에서는 진행 링을 포함한 큰 동작을 즉시 완료한다.
- 레이아웃 이동 애니메이션은 콘텐츠 점프와 포커스 손실을 만들지 않아야 한다.

## 7. CSS·컴포넌트 작성 규칙

- 토큰은 `shared/styles/tokens.css`에 CSS Custom Property로 정의한다.
- 전역 reset·font·page background는 `globals.css`에 둔다.
- 컴포넌트 전용 스타일은 컴포넌트 가까이에 두고 전역 selector 의존을 줄인다.
- `!important`, ID selector, 3단계 이상의 깊은 selector를 사용하지 않는다.
- 숫자 색상값을 컴포넌트에 직접 반복하지 않는다.
- 페이지는 공통 UI를 조립하고 도메인 로직을 직접 구현하지 않는다.
